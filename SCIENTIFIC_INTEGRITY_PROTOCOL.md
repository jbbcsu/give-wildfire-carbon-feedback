# Scientific integrity and evidence protocol

This protocol is binding for all analysis, manuscript, code, and status
updates in this project. There is no circumstance in which missing data,
failed analysis, an inaccessible source, or an inconvenient result may be
replaced with an invented value or claim.

## Evidence classes

Every quantitative statement must belong to exactly one class:

1. **Observed source data:** downloaded from a named source with version,
   license, retrieval record, file size, and checksum.
2. **Derived empirical result:** generated by tracked code from identified
   source data and a frozen configuration, with an output artifact and
   validation record.
3. **Published result:** attributed to a primary source with a DOI or stable
   archive; it is never presented as this project's estimate.
4. **Synthetic test:** generated solely to verify code behavior and labeled
   `synthetic` in code, output, documentation, and discussion.
5. **Diagnostic pilot:** a real-data workflow or predictive check that has not
   cleared the inferential gates; it is labeled `diagnostic` and cannot enter
   the manuscript's substantive results or SCC calculation.
6. **Assumption or scenario:** a transparent modeling choice, not an empirical
   estimate. Fixed, trend, and upper adaptation cases are in this class until
   independently estimated.
7. **Planned or unavailable:** no result exists. Use an explicit placeholder
   or report the blocker; never fill the gap by inference or plausibility.

## Prohibited practices

- Inventing, altering, or completing observations, citations, coefficients,
  uncertainty intervals, model output, sample sizes, or SCC values.
- Silently imputing missing observations, changing units, redefining samples,
  or substituting a different dataset for an unavailable source.
- Describing synthetic tests, simulations, literature values, or diagnostic
  fits as observed empirical results.
- Reporting a causal effect from predictive fit or fixed-effects correlation
  without an identification argument that supports that language.
- Selecting a weather feature, drought metric, model, sample, or adaptation
  case because it produces a preferred sign or a larger SCC.
- Transferring U.S. or regional coefficients globally without a documented
  transportability design and validation.
- Suppressing null, sign-changing, failed, or inconvenient specifications.
- Manually entering manuscript result values when they can be generated from
  a tracked results artifact.

## Mandatory stop-and-report conditions

Stop the affected analysis and state the limitation when a source is missing,
corrupt, incomplete, inaccessible, ambiguously licensed, or inconsistent with
its manifest; when keys, units, calendars, or coordinate systems cannot be
reconciled; when the estimand is not identified; when an analysis falls
outside observed support; or when a model fails a predeclared validation gate.

The next action must be one of: acquire a valid source; use a documented,
scientifically defensible alternative and rerun validation; narrow the claim;
report a partial-identification or sensitivity result; or request guidance
from the project lead. A failed or null analysis is itself reportable and must
not be hidden.

## Result-release gate

A numerical agricultural-damage or SCC result is not releasable until all of
the following hold:

- source and derived-data provenance are complete and checksums verify;
- the analysis command, configuration, seed/draw IDs, software environment,
  and code commit are recorded;
- units, sample counts, missingness, joins, and aggregation identities pass;
- spatial, temporal, and extreme-event holdouts are reported;
- extrapolation and incomplete crop/value coverage are quantified;
- the response is separated from temperature, CO2, irrigation, adaptation,
  and welfare effects according to the registered estimand;
- pulse/base draws are matched and converge under smaller pulse sizes;
- MooreAg is replaced rather than stacked, and no other GIVE overlap is known;
- uncertainty and alternative defensible specifications are retained;
- tables and figures are regenerated from machine-readable artifacts; and
- `RESULTS_STATUS.md` explicitly promotes the result from diagnostic to its
  permitted claim class.

Until then, the manuscript must show a placeholder or clearly labeled
diagnostic—not an estimated SCC.

## AI-assisted work

AI-generated prose, code, and literature suggestions have no evidentiary
status. Citations must resolve to the asserted primary source; code must pass
tests; and every numerical claim must trace to source data or a generated
artifact. Uncertainty must be stated rather than filled with a plausible
answer. The independent reviewer is encouraged to assume this repository's
claims are unverified until reproduced.

## Current audit finding (2026-08-22)

The repository reports no agricultural SCC value and exports no empirical
response coefficient for SCC use. Existing numerical model comparisons are
explicitly labeled real-data diagnostics, while component tests are labeled
synthetic. These labels do not prove correctness; they define the maximum
permitted interpretation pending independent reproduction.
