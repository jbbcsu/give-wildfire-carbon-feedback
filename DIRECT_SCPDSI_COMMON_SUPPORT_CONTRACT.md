# Direct-weather/scPDSI common-support contract

## Purpose and boundary

`scripts/build_direct_scpdsi_common_support.py` creates a data-only basis for a
future predictive comparison between two alternative moisture representations:

1. crop-calendar direct weather; and
2. historical CRU scPDSI.

The builder does not estimate a response, emit a coefficient, select a model,
project future climate, calculate damage, or calculate an SCC. Predictive
comparison remains unauthorized. In particular, this contract is not evidence
that either candidate has a causal yield effect.

## Source contracts

The direct input must be a validated
`gdhy_aggregate_irrigation_distribution_candidate_v1` table. The drought input
must be a validated `gdhy_aggregate_irrigation_scpdsi_candidate_v1` table whose
source role is `historical_benchmark_not_future_scc_input`. Both must contain
one fixed-MIRCA-area-weighted row per crop, grid cell, and harvest year. Their
weight source, weight vintage, allocation order, and outcome definition must
agree exactly.

Features are declared explicitly on the command line. Direct features cannot
contain PDSI/scPDSI/SPEI terms. Selections must be subsets of the registered
three-stage feature lists generated by the two upstream allocator modules;
name-pattern matches alone are insufficient. Every selected feature must have
a non-Boolean numeric dtype and is canonicalized to `float64`. The entire
scPDSI input—not merely the declared subset—is screened for primitive or
derived precipitation, temperature, dry-spell, and wet-extreme columns. A
leaked direct-weather column causes failure.

## Common support and outcomes

The exact key is:

`harvest_year, lat, lon_360, crop`

Duplicate or missing keys fail. `yield_observed` and `yield_t_ha` must agree
exactly for every retained key; observed yields must be finite and positive.
Unequal family support fails by default. The optional
`--authorize-support-intersection` flag permits only a whole-key inner
intersection. It does not impute either family. The audit reports input,
family-only dropped, and common rows and observed outcomes, including crop and
year bounds.

## Structurally separate views

The builder requires two output paths rather than emitting one wide predictor
matrix:

- the direct view contains only `direct__*` feature columns;
- the drought view contains only `scpdsi__*` feature columns.

Both views retain identical, deterministically ordered keys and outcomes. This
separation makes the two families alternative candidate views; it does not
authorize stacking or adding their effects. Every row carries exact Boolean
gates that prohibit stacking, fitting, coefficient output, causal
interpretation, damage calculation, future projection, and SCC use.

## Provenance and immediate-input recomputation

The JSON audit records the input and output file paths and SHA-256 hashes,
registered and selected source-to-prefixed feature mappings, support losses,
and all authorization gates. Unknown audit fields, including unknown
`*_authorized` fields, fail validation.

`scripts/validate_direct_scpdsi_common_support.py` checks the four file hashes,
validates each view independently, rereads both immediate candidate tables,
recomputes both views and the support audit, and requires exact frame equality.
It does **not** rerun either allocator from raw climate, crop-calendar, yield,
or irrigation-share sources and does not bind an upstream validation receipt.
Running the applicable upstream validators and retaining their receipts is an
explicit external prerequisite. Both the audit and validation result record
`upstream_validation_receipts_bound=false` and
`upstream_raw_source_recomputation_performed=false`; they must not be described
as full upstream-source validation.

Example data-only assembly (paths below should remain under ignored
`data/interim` and `outputs` locations):

```bash
./.venv/bin/python scripts/build_direct_scpdsi_common_support.py \
  --direct-input DIRECT_DISTRIBUTION_CANDIDATE.parquet \
  --scpdsi-input HISTORICAL_SCPDSI_CANDIDATE.parquet \
  --direct-feature tmean_c \
  --direct-feature precip_mm \
  --scpdsi-feature season_scpdsi_mean \
  --authorize-support-intersection \
  --direct-out COMMON_DIRECT_VIEW.parquet \
  --scpdsi-out COMMON_SCPDSI_VIEW.parquet \
  --audit-out COMMON_SUPPORT_AUDIT.json
```

Validation:

```bash
./.venv/bin/python scripts/validate_direct_scpdsi_common_support.py \
  --direct-view COMMON_DIRECT_VIEW.parquet \
  --scpdsi-view COMMON_SCPDSI_VIEW.parquet \
  --audit COMMON_SUPPORT_AUDIT.json \
  --direct-input DIRECT_DISTRIBUTION_CANDIDATE.parquet \
  --scpdsi-input HISTORICAL_SCPDSI_CANDIDATE.parquet
```

Synthetic tests cover duplicate keys, exact outcome disagreement, unauthorized
and authorized support intersection, direct-weather leakage into the drought
family, Boolean gate tampering, file-hash tampering, and immediate-input
recomputation.
